# 多艺术家署名：交付与验收

## 交付状态

本轮已修改四个仓库：

| 仓库 | 改动 |
|---|---|
| `032music-server` | 结构化标签读取、旧 MusicAutoTagger 多 MBID 严格恢复、文件身份对应证据、单曲人工修正/恢复/撤销、合并保护 |
| `MusicAutoTagger` | MusicBrainz 逐人姓名列表、ARTISTS / ALBUM_ARTISTS 容器多值写入、审核快照复制、旧列表失效处理 |
| `MusicBridge` | 复用多人选择器、完整刷新后缓存/队列身份更新、下载记录持久化艺人引用（DB v19） |
| `032player-rs` | 多人引用贯穿视图、主要入口多人选择、队列元数据刷新不重建播放会话 |

当时发出的包：Rust 正式版 v0.2.12，Android 正式版 v1.1.1（versionCode 6）。服务端与刮削器推送 main 时由 GitHub Actions 构建 Docker 镜像。构建是否成功以 GitHub Actions 为准；没有操作真实音乐文件或真实服务端数据库。

本期不做批量人工修正、不自动创建艺术家、不在线查询 MusicBrainz 猜测拆分、不修改现有 API 版本。Rust 文字署名改为 `姓名 | 姓名`，每个姓名独立跳转；右键“转到艺人”等单一入口保留多人选择器。

专辑分组按专辑艺人判断，不再用曲目合唱覆盖专辑归属：A 的个人专辑含 A + B 合唱，在 A 页仍为个人发行，在 B 页为“参与作品”；非合辑的共同专辑署名才归“合作作品”。VA / Various Artists 合辑中的合唱归各演唱者的“参与作品”。多人曲目引用及双方曲目查询保持不变。本项分类修复只需部署服务端并重新进入艺人页，不需要再次重扫或升级 Rust 客户端。

## 为什么已有曲目能修

旧刮削器写入：

```text
ARTIST = Mori Calliope, 常闇トワ
MUSICBRAINZ_ARTISTID = <person-1-uuid>; <person-2-uuid>
```

服务端现在仅在有效 MBID 数量与旧格式姓名分段数量严格一致时恢复多人。结构化 `ARTISTS` 一直优先；无 MBID、重复/无效 ID、人数不符时不按逗号猜测。

新刮削器写逐人的 `ARTISTS`，减少歧义。没有强制重新刮削全部文件。

## 安全升级顺序

1. **备份服务端数据库。** 新版本新增迁移 067-069，旧二进制不能作为直接降级方案，回退需使用升级前备份。
2. 部署修改后的服务端，执行一次**完整扫描**，不是增量扫描。
3. 找一首双人合作曲目，检查 `GET /api/v1/tracks/{id}`：`artists` 应为两个人，各有独立 ID；`artist` 仍可显示拼接文字。
4. Android 安装新版后执行完整曲库刷新；Rust 重新进入专辑/曲目页或重启加载。
5. 最后升级刮削器，之后新处理/重写标签的文件会带结构化多人姓名。

对于歧义文件，服务端专辑页曲目署名后的“修正演唱者”可单曲处理。选择已有艺术家、预览后确认；不改变曲目 ID。

## 一次性验收清单

- [ ] 截图所示曲目：Mori Calliope、常闇トワ 分别有个人页，均能找到这首歌。
- [ ] Android 点多人艺人文字出现选择器；选择任何一位均进入正确页面。
- [ ] Rust 曲目列、版本列表、专辑头、专辑卡片、首页横幅、播放条、右栏、全屏显示 `姓名 | 姓名`，点击各姓名直接进入对应页面。
- [ ] 个人专辑含合唱，在专辑艺人页仍为个人发行，在客串方页为“参与作品”；共同署名的非合辑发行在双方页为“合作作品”。
- [ ] VA 专辑中的双人合唱及单人收录，在各演唱者个人页均归“参与作品”；双方仍能找到合唱曲目。
- [ ] 单人曲目仍直接打开；作词/作曲等单名链接仍直接打开，不弹无关演唱者选择器。
- [ ] 真正组合名、带逗号或 & 的名字没有被无条件拆分。
- [ ] 曲目艺人与专辑艺人不同的专辑，发行署名不被曲目修正覆盖。
- [ ] 人工修正后完整重扫，修正仍有效；恢复默认使用最新标签；撤销预览结果正确。
- [ ] Android 对已经下载的歌曲执行联网完整刷新，断网重启后多人信息还在，音频不重下，下载大小不变。
- [ ] 播放中刷新艺人元数据不中断、不跳歌、不多记一次播放，推荐上下文仍在。
- [ ] 歌单、曲目收藏、播放历史与曲目 ID 不变。

没有有效曲库关联的旧合作署名可能因底层/撤销历史而保留实体，但不应在正常列表中冒充活跃艺人。若仍是专辑艺人，则继续显示是预期行为。

### 已通过

- 服务端：`go test ./...` 全量通过，新增合成标签、重扫/恢复/撤销、并发表单、CSRF、合并回退等用例。

- Android：Debug APK 构建、所选多人 JSON / 元数据刷新 / 幕后署名 / 上报路由 / Sonos 队列 35 项纯 JVM 测试通过。
- Rust `|` 分隔姓名的软件渲染截图，模拟点击两个姓名分别得到 ID 10 / 20；服务端管理页 1280 / 375 宽度实际加载共享样式检查，无横向溢出。

- Windows 实际运行、Android 真机播放及真实曲库样本尚未验证。
- Windows 安装包与正式签名 APK 已安排由标签触发 GitHub Actions 生成；下载状态需以 Release 页面为准。
